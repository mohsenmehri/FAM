# ۰.۵ — Windows و ابزارهای خط فرمان

**سطح:** مقدماتی مرحلهٔ صفر؛ مستقل از اهداف رسمی CCNA. **پیش‌نیاز:** ۰.۱ و ۰.۳؛ درس Linux پیش‌نیاز نیست. **وضعیت:** پیش‌نویس؛ تمام فرمان‌ها و خروجی‌ها پیشنهادی و اجرا‌نشده‌اند. نسخهٔ Windows و VM هدف انتخاب نشده‌اند.

## هدف

تفاوت CMD و PowerShell، کاربر و سطح اختیار، سرویس، Device Manager و Event Viewer را توضیح دهید و با مشاهدهٔ غیرمخرب، وضعیت اولیهٔ سیستم و شبکه را تحلیل کنید؛ بدون فرض اینکه نتیجهٔ یک ابزار، سلامت کل مسیر را ثابت می‌کند.

## ۱. محیط‌ها و هویت

**Command Prompt یا CMD** و **PowerShell** دو محیط خط فرمان Windows با نحو و قابلیت‌های متفاوت‌اند. PowerShell خروجی بسیاری از فرمان‌هایش را به‌صورت شیء پردازش می‌کند، در حالی که نباید فرمان‌های هر محیط را بی‌بررسی در دیگری یکسان فرض کرد. رابط گرافیکی، برنامه‌ها و خط فرمان از همان سیستم‌عامل و سیاست‌های امنیتی استفاده می‌کنند.

کاربر معمولی و نشست دارای اختیار بالا یکسان نیستند. UAC و سیاست سازمان می‌توانند درخواست افزایش اختیار را کنترل کنند. برای مشاهدهٔ ساده، ابتدا از حساب استاندارد و ابزار بدون افزایش اختیار استفاده کنید؛ خطای دسترسی مجوزی برای دور زدن سیاست نیست.

## ۲. سرویس، دستگاه و رویداد

- **Service:** قابلیتی که Windows مدیریت می‌کند؛ ممکن است با فرایند اختصاصی یا مشترک اجرا شود. وضعیت Running اثبات پاسخ صحیح به درخواست نیست.
- **Device Manager:** ابزار مشاهدهٔ دستگاه‌های شناسایی‌شده و وضعیت گزارش‌شدهٔ آن‌ها؛ وجود کارت شبکه به معنی سلامت ارتباط انتهابه‌انتها نیست.
- **Event Viewer:** ابزار مشاهدهٔ رویدادهای ثبت‌شده؛ زمان، منبع، شناسه و متن خطا را همراه با شرایط مشکل بررسی کنید. یک رویداد به‌تنهایی علت ریشه‌ای را ثابت نمی‌کند.

## ۳. سناریوی سازمانی

یک کاربر می‌گوید پورتال داخلی باز نمی‌شود. روی دستگاه، برنامه‌های محلی اجرا می‌شوند. باید میان تنظیمات دستگاه، ارتباط، نام سرویس و خود سرویس تفاوت گذاشت؛ هیچ نشانه‌ای به‌تنهایی عامل خرابی را مشخص نمی‌کند.

```text
[Windows Client] → [شبکه سازمان] → [میزبان پورتال / سرویس]
       │                                      │
 تنظیم رابط و نام                        وضعیت سرویس و لاگ
```

این نمودار مفهومی است؛ آدرس و تجهیزات واقعی مشخص نشده‌اند.

## ۴. فرمان‌های پیشنهادی غیرمخرب

**پیشنهادی، اجرا‌نشده؛ رفتار و دسترسی به نسخه و سیاست محیط بستگی دارد.** برای IP آزمایشی از آدرس مستنداتی استفاده شده است؛ الزاماً مقصد پاسخ‌گو وجود ندارد.

| محیط و فرمان | اثر | تفسیر |
|---|---|---|
| CMD: `whoami` | نمایش هویت جاری | هویت را نشان می‌دهد، نه تمام دسترسی مؤثر را |
| CMD: `ipconfig` | نمایش پیکربندی IP رابط‌ها | وجود IP به معنی سالم بودن کل شبکه نیست |
| CMD: `ping 192.0.2.1` | ارسال درخواست آزمایشی | نبود پاسخ می‌تواند از فیلتر یا نبود مقصد باشد |
| PowerShell: `Get-Location` | نمایش پوشهٔ جاری | مبنای مسیر نسبی را مشخص می‌کند |
| PowerShell: `Get-Service` | فهرست وضعیت گزارش‌شدهٔ سرویس‌ها | Running به معنی پاسخ صحیح سرویس نیست |

در PowerShell `Get-Service` خروجی ساخت‌یافته با فیلدهایی مانند `Status` و `Name` می‌دهد. در این درس صرف مشاهده مطرح است؛ تغییر، توقف یا راه‌اندازی سرویس مجاز نیست.

## ۵. کاربرگ مستقل

**وضعیت: طراحی‌شده و اجرا‌نشده.** محیط موردنیاز: VM مستقل Windows با حساب آزمایشی استاندارد، بدون اتصال به شبکه یا دادهٔ عملیاتی. انتخاب محصول، نسخه و نوع شبکهٔ VM جداگانه در درس ۰.۸ انجام می‌شود. قبل از اجرا مجوز، نسخه و ایزوله‌بودن باید تأیید شوند.

1. در CMD فرمان `whoami` را اجرا و نام حساب را ثبت کنید؛ آن را با حساب مورد انتظار مقایسه کنید.
2. `ipconfig` را اجرا و رابط‌های نمایش‌داده‌شده و وجود یا نبود IP را ثبت کنید؛ خروجی واقعی ممکن است متفاوت باشد.
3. در PowerShell، `Get-Location` و سپس `Get-Service` را اجرا کنید. برای یک سرویس، نام و وضعیت گزارش‌شده را ثبت کنید؛ هیچ سرویسی را تغییر ندهید.
4. از طریق Device Manager وضعیت گزارش‌شدهٔ کارت شبکه را مشاهده کنید. در Event Viewer فقط رویدادهای مربوط به زمان فرضی را بررسی کنید؛ اطلاعات حساس را منتشر نکنید.
5. توضیح دهید کدام مشاهده‌ها به سیستم محلی و کدام فرضیه‌ها به شبکه یا سرویس مقصد مربوط‌اند.

**خروجی مورد انتظار، نه مشاهده‌شده:** `whoami` هویت جاری، `ipconfig` اطلاعات رابط‌های قابل مشاهده و `Get-Location` مسیر جاری را نشان می‌دهد. نام‌ها، آدرس‌ها و سرویس‌ها را نباید از این متن به‌عنوان نتیجهٔ واقعی کپی کرد.

## ۶. عیب‌یابی

| نشانه | بررسی مرحله‌ای | پرهیز |
|---|---|---|
| IP مورد انتظار دیده نمی‌شود | رابط صحیح، وضعیت دستگاه و روش تنظیم را با سیاست محیط بررسی کنید | تغییر خودسرانهٔ IP عملیاتی |
| سرویس Running است اما پاسخ نمی‌دهد | درخواست مجاز، لاگ‌ها، وابستگی و مسیر را بررسی کنید | نتیجه‌گیری از وضعیت سرویس به‌تنهایی |
| دسترسی به ابزار رد می‌شود | هویت، مجوز و سیاست سازمان را بررسی کنید | اجرای ابزار با اختیار بالا بدون مجوز |
| رویداد خطا دیده می‌شود | زمان، منبع و ارتباطش با رخداد را مقایسه کنید | فرض اینکه هر خطای قدیمی علت مشکل فعلی است |

## ۷. سؤال‌های سناریویی و پاسخ

1. **CMD و PowerShell یکی‌اند؟** خیر، محیط‌ها و نحو و مدل پردازش خروجی آن‌ها تفاوت دارند.
2. **`whoami` چه چیزی را ثابت می‌کند؟** هویت گزارش‌شدهٔ نشست جاری را، نه تمام دسترسی‌های مؤثر را.
3. **`ipconfig` یک IP نشان می‌دهد؛ آیا پورتال سالم است؟** خیر، مسیر و سرویس باید جداگانه بررسی شوند.
4. **Ping پاسخ ندارد؛ آیا کارت شبکه خراب است؟** نه الزاماً؛ فیلتر، مقصد و مسیر نیز ممکن‌اند.
5. **Device Manager دستگاه را نشان می‌دهد؛ شبکه حتماً سالم است؟** خیر؛ شناسایی دستگاه، ارتباط انتهابه‌انتها را تضمین نمی‌کند.
6. **Service در Running است ولی درخواست شکست می‌خورد؛ چه می‌کنید؟** درخواست مجاز، لاگ، وابستگی و شبکه را بررسی می‌کنیم.
7. **یک خطای دیروز در Event Viewer هست؛ علت خطای امروز است؟** بدون تطبیق زمان و شواهد نمی‌توان چنین نتیجه گرفت.
8. **PowerShell مسیر جاری را چگونه در مثال نشان می‌دهد؟** با `Get-Location`؛ نتیجه بسته به نشست فرق دارد.
9. **ابزار خطای دسترسی می‌دهد؛ فوراً نشست را مدیر کنیم؟** خیر؛ ابتدا ضرورت و مجوز سازمان بررسی شود.
10. **چرا VM مستقل؟** برای محدود کردن ریسک تغییر و افشای داده؛ ایزوله بودن باید واقعاً کنترل شود.
11. **کاربری گزارش مشکل دارد، اما کاربر دیگری ندارد؛ چه بررسی می‌کنید؟** تفاوت دستگاه، هویت و مسیر دو کاربر را با شواهد مقایسه می‌کنیم.
12. **چرا خروجی نمونه را نتیجهٔ واقعی نمی‌نامیم؟** چون فرمان‌ها روی نسخه و محیط مشخص اجرا و ثبت نشده‌اند.

## واژه‌نامه و چک‌لیست

CMD: محیط خط فرمان؛ PowerShell: محیط مدیریت و پردازش اشیا؛ UAC: سازوکار کنترل افزایش اختیار؛ Service: قابلیت مدیریت‌شده؛ Event Viewer: نمایش رویدادهای ثبت‌شده.

- [ ] هویت جاری، سطح اختیار و مجوز مؤثر را یکی نمی‌گیرم.
- [ ] وضعیت دستگاه، ارتباط و سرویس را جدا بررسی می‌کنم.
- [ ] قبل از تغییر عملیاتی مجوز و برنامهٔ بازگشت می‌گیرم.
- [ ] نمونه‌ها را با شواهد واقعی اشتباه نمی‌گیرم.
