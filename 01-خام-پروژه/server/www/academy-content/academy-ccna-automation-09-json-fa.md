# CCNA AUT-09 — اجزای دادهٔ JSON

**سطح:** CCNA. **پیش‌نیاز:** AUT-07. **هدف رسمی:** `6.7` تشخیص اجزای دادهٔ JSON-encoded؛ در این درس شش نوع مقدار شامل Object، Array، String، Number، Boolean و Null آمده است. **وضعیت:** پیش‌نویس محتوایی؛ نمونه‌ها طراحی‌شده و **اجرا‌نشده**؛ هیچ API واقعی در دسترس نبوده است.

## اهداف

1. شش نوع مقدار JSON را تشخیص دهید و در نمونهٔ آموزشی مکان هرکدام را پیدا کنید.
2. خطاهای نگارشی را **بدون ابزار** پیدا کنید.
3. با نشانه‌گذاری برای رسیدن به یک مقدار تودرتو کار کنید.
4. بدانید کدام ساختارها در JSON **مجاز نیستند** — و چرا.

## ۱. ساختار JSON — شش نوع مقدار

در نحو استاندارد JSON شش نوع مقدار داریم: **Object، Array، String، Number، Boolean و null**. Object و Array ساختارهای تودرتو می‌سازند؛ Boolean دو مقدار `true`/`false` دارد. کلید Object همواره String است.

| جزء | نماد | مثال | کاربرد در شبکه |
|---|---|---|---|
| **Object** | `{ }` | `{"hostname": "SW1"}` | یک دستگاه، یک VLAN |
| **Array** | `[ ]` | `[10, 20, 30]` | فهرست VLANها، فهرست دستگاه‌ها |
| **String** | `" "` | `"USERS"` | نام، آدرس IP، MAC |
| **Number** | ارقام | `10`، `3.14` | VLAN ID، پورت، Uptime |
| **Boolean** | `true`/`false` | `true` | وضعیت فعال/غیرفعال |
| **null** | `null` | `null` | مقدار JSON صریح؛ تفسیرش به Schema/API بستگی دارد |

**نکتهٔ ظریف:** `"10"` (String) و `10` (Number) **یکسان نیستند**. یک API ممکن است VLAN ID را String بفرستد و API دیگر Number. در Parse کردن، این تفاوت باعث خطا می‌شود.

## ۲. نمونهٔ کامل با تفسیر

```json
{
  "hostname": "SW1",
  "management_ip": "10.10.0.11",
  "enabled": true,
  "uptime_days": 12,
  "cpu_percent": 4.7,
  "vlans": [
    { "id": 10, "name": "USERS", "active": true },
    { "id": 20, "name": "VOICE", "active": true },
    { "id": 99, "name": "MGMT",  "active": false }
  ],
  "last_error": null,
  "interfaces": {
    "GigabitEthernet0/1": { "status": "up",   "speed": 1000 },
    "GigabitEthernet0/2": { "status": "down", "speed": 0 }
  }
}
```

| بخش | نوع | مقدار |
|---|---|---|
| `"hostname"` | String | `SW1` |
| `"uptime_days"` | Number (صحیح) | `12` |
| `"cpu_percent"` | Number (اعشاری) | `4.7` |
| `"vlans"` | Array از ۳ Object | — |
| `"vlans"[1]["name"]` | String | `VOICE` |
| `"last_error"` | null | مقدار خالی/نامشخص طبق قرارداد این پاسخ نمونه؛ باید Schema را بررسی کرد |
| `"interfaces"` | Object تودرتو | کلیدها نام Interface هستند |

**نکتهٔ مهم دربارهٔ `null`:** `null` با `""` (رشتهٔ خالی) و `0` و `false` **متفاوت** است:

| مقدار | معنا |
|---|---|
| `null` | مقدار JSON صریحی برای این فیلد؛ معنای کسب‌وکاری را Schema/API تعیین می‌کند |
| `""` | رشتهٔ خالی — مقدار دارد ولی خالی است |
| `0` | عدد صفر — مقدار دارد و صفر است |
| `false` | بولین — مقدار دارد و نادرست است |

همچنین **کلیدِ غایب** با کلیدی که مقدارش `null` است متفاوت است: اولی در Object وجود ندارد، دومی صریحاً وجود دارد و مقدار JSON آن `null` است. این تفاوت را با قرارداد API تفسیر کنید.

در Python، JSON `null` معمولاً به `None` Parse می‌شود. اگر در Script بنویسید `if not value:`، مقدارهای `None`، `""`، `0` و `False` **همه** Falsy ارزیابی می‌شوند. اگر فقط JSON `null` را می‌خواهید تشخیص دهید، `if value is None:` بزنید. این ظرافت در Automation واقعی مهم است: VLAN ID = 0 خطاست، ولی Script شما ممکن است آن را با «تعریف نشده» یکی بگیرد.

## ۳. نشانه‌گذاری برای رسیدن به مقدار

**JSONPath** برای Query ساختار JSON به‌کار می‌رود و `$` ریشه را نشان می‌دهد. استاندارد IETF RFC 9535 نحو پایه را تعریف می‌کند، اما ابزارها ممکن است Dialect یا قابلیت‌های متفاوت داشته باشند؛ نحو دقیق ابزار مقصد را بررسی کنید:

| نماد | معنا | نمونه |
|---|---|---|
| `$` | ریشه | `$` |
| `.key` | کلید Object | `$.hostname` |
| `[n]` | عنصر n-ام Array (از صفر) | `$.vlans[0]` |
| `[*]` | همهٔ عناصر | `$.vlans[*].name` |
| `..` | جستجو در همهٔ سطوح | `$..name` |

مثال‌ها روی همان JSON بالا:

| JSON Path | نتیجه |
|---|---|
| `$.hostname` | `"SW1"` |
| `$.vlans[0].id` | `10` |
| `$.vlans[1].name` | `"VOICE"` |
| `$.vlans[*].name` | `["USERS", "VOICE", "MGMT"]` |
| `$.interfaces["GigabitEthernet0/1"].status` | `"up"` |
| `$..status` | `["up", "down"]` |
| `$.last_error` | `null` |

**نکتهٔ عملی:** کلیدهایی که `/` یا فاصله دارند (`GigabitEthernet0/1`) باید در `[" "]` یا با Escape نوشته شوند. این یکی از رایج‌ترین خطاها در اسکریپت‌های شبکه است.

**تفاوت با نشانه‌گذاری نقطه‌ای سادهٔ پایتون:** `obj["vlans"][0]["name"]` معادل `$.vlans[0].name` است. JSON Path برای Query و فیلتر است؛ نشانه‌گذاری پایتون برای دسترسی مستقیم.

## ۴. قواعد و خطاهای رایج

| قاعده | درست | غلط | چرا |
|---|---|---|---|
| کلید در `" "` | `{"id": 10}` | `{id: 10}` | کلید باید String باشد |
| کاما بین عناصر | `[1, 2]` | `[1 2]` | کمای جاافتاده |
| **بدون کامای آخر** | `[1, 2]` | `[1, 2,]` | استاندارد JSON اجازه نمی‌دهد |
| بدون کامنت | `{"a": 1}` | `{"a": 1} // note` | کامنت مجاز نیست |
| `true`/`false` کوچک | `true` | `True`، `TRUE` | JSON حساس به حروف است |
| `null` کوچک | `null` | `NULL`، `None` | همان |
| بستن براکت‌ها | `{"a": [1]}` | `{"a": [1}` | ناسازگاری |
| بدون `NaN` / `Infinity` | `0` | `NaN` | استاندارد JSON این‌ها را ندارد |
| escape در رشته | `"a\"b"` | `"a"b"` | کوتیشن داخل رشته |
| فاصله مجاز است | `{ "a" : 1 }` | — | فاصله اثر ندارد |

**نکتهٔ مهم دربارهٔ کامای آخر:** بعضی ابزارها (مثل JSON5 یا Python Dict) آن را می‌پذیرند، ولی **JSON استاندارد** نمی‌پذیرد. اگر API شما آن را رد کند، همین جزئیات کوچک می‌تواند ساعت‌ها وقت بگیرد.

### خطاهای پاسخ واقعاً رایج در شبکه

1. **کلید با حرف بزرگ/کوچک متفاوت:** `"Hostname"` در برابر `"hostname"`. JSON حساس به حروف است.
2. **عدد در برابر رشته:** `"vlan_id": "10"` در برابر `10`. اگر مقایسهٔ عددی کنید، دومی را رد می‌کنید.
3. **`null` در جایی که Array انتظار می‌رفت:** `"vlans": null` نه `"vlans": []`. اگر با `for` روی آن حرکت کنید، خطای TypeError می‌گیرید.
4. **تودرتویی متفاوت:** API یک نسخه `{"data": {"devices": [...]}}` و نسخهٔ دیگر `{"devices": [...]}` می‌دهد. **همیشه ساختار را قبل از Parse کردن بررسی کنید.**

## ۵. سناریوی طراحی‌شده

**PNETLab مستقل، طراحی‌شده و اجرا‌نشده:** پاسخ فرضی API شامل فهرست دستگاه‌ها و VLANها. **نمونهٔ زیر طراحی‌شده است؛ هیچ API واقعی فراخوانی و هیچ داده‌ای Parse نشده است.**

```json
{
  "response": [
    {
      "hostname": "SW1",
      "managementIpAddress": "10.10.0.11",
      "reachabilityStatus": "Reachable",
      "vlans": [
        { "vlanId": 10, "vlanName": "USERS" },
        { "vlanId": 20, "vlanName": "VOICE" }
      ]
    },
    {
      "hostname": "SW2",
      "managementIpAddress": "10.10.0.12",
      "reachabilityStatus": "Unreachable",
      "vlans": null
    }
  ]
}
```

**تحلیل این پاسخ — و این نکته‌ای است که در بیشتر درس‌ها جا می‌افتد:**

1. `response` یک **Array** است، نه Object. هر عنصر یک دستگاه است.
2. `SW2` وضعیت `Unreachable` دارد و `vlans` آن `null` است. اگر Script شما بنویسد:

```python
for vlan in device["vlans"]:  # TypeError اگر vlans برابر None باشد
    ...
```

پیش از پیمایش، وضعیت و نوع فیلد را بررسی کنید؛ `.get()` همچنین کلیدِ غایب را پوشش می‌دهد:

```python
vlans = device.get("vlans")
if device.get("reachabilityStatus") == "Reachable" and isinstance(vlans, list):
    for vlan in vlans:
        ...
else:
    # پاسخ را طبق قرارداد API ثبت/گزارش کن؛ «خالی» فرضش نکن
    ...
```

3. این ساختار دفاعی (**Defensive Parsing**) تفاوت بین Scriptی است که در Production کار می‌کند و Scriptی که فقط روی دادهٔ نمونه کار می‌کند.

## ۶. کاربرگ مستقل JSON و Parsing (بدون نیاز به PNETLab)

هدف رسمی `Recognize` است؛ تمرینِ کاغذی/ویرایشگر و Parser محلی برای شناخت ساختار کافی است. PNETLab ربطی به اعتبارسنجی Syntax JSON ندارد. این تمرین طراحی شده و اجرا‌نشده است.

1. یک پاسخ JSON برای سه دستگاه با دو VLAN هر کدام بنویسید.
2. مسیرهای نشانه‌گذاری برای این مقادیر را بنویسید:
   - نام VLAN دوم دستگاه اول
   - IP دستگاه سوم
   - همهٔ نام‌های VLAN در همهٔ دستگاه‌ها
3. **عمداً** سه خطای نگارشی در فایل ایجاد کنید (کامای آخر، کامنت، `True` با حرف بزرگ). با یک Parser خطاها را ببینید و اصلاح کنید.
4. یک مقدار `null` بگذارید و Scriptی بنویسید که بدون خطا از آن رد شود.
5. یک فیلد را به String تبدیل کنید (`"vlanId": "10"`) و ببینید مقایسهٔ عددی چگونه شکست می‌خورد.
6. اگر به یک API واقعی دسترسی دارید، پاسخ **واقعی** را با `curl` بگیرید و ساختارش را با نمونهٔ درس مقایسه کنید. تفاوت‌ها را ثبت کنید.

**هشدار:** اگر API واقعی در دسترس نیست، «اجرا نشد» را صریح بنویسید. نمونهٔ طراحی‌شده، شاهد اجرا نیست.

هیچ‌کدام اجرا نشده و هیچ دادهٔ واقعی Parse نشده است.

## ۷. سؤال‌ها و پاسخ

1. **چند نوع مقدار در JSON استاندارد داریم؟** شش: Object، Array، String، Number، Boolean و `null`. Boolean دو literal یعنی `true` و `false` دارد؛ `null` نوع مستقل است.

2. **Object چیست؟** مجموعه‌ای از جفت‌های کلید-مقدار در `{ }`.

3. **Array چیست؟** فهرست مرتب در `[ ]`؛ می‌تواند هر نوعی داشته باشد.

4. **تفاوت `10` و `"10"` چیست؟** اولی Number، دومی String. مقایسه و مقایسهٔ نوعی متفاوتند.

5. **`null` چه معنایی دارد؟** مقدار JSON صریح `null` است؛ تفسیر آن را قرارداد/API تعیین می‌کند و با کلیدِ غایب، `""`، `0` و `false` تفاوت دارد.

6. **آیا کامنت در JSON مجاز است؟** نه.

7. **آیا کامای آخر مجاز است؟** نه.

8. **کلید باید در چه باشد؟** در کوتیشن دوتایی.

9. **Boolean چه مقادیری دارد؟** `true` و `false` با حروف کوچک.

10. **`$.vlans[0].name` چه چیزی را نشان می‌دهد؟** نام اولین VLAN.

11. **`$.vlans[*].name` چه تفاوتی دارد؟** همهٔ نام‌ها را برمی‌گرداند، نه فقط اولی.

12. **اگر `vlans` مقدار `null` داشته باشد و با `for` روی آن حرکت کنید چه می‌شود؟** خطای زمان اجرا. باید قبلش `is not None` بررسی شود.

13. **JSONPath چیست؟** نحو Query برای انتخاب مقدار در ساختار تودرتو؛ استاندارد پایه تعریف شده، اما Dialect/پشتیبانی ابزارها را باید بررسی کرد.

14. **چرا کلید `GigabitEthernet0/1` مشکل‌ساز است؟** چون `/` دارد و باید Escape یا در `[" "]` نوشته شود.

15. **JSON برای چه استفاده می‌شود؟** انتقال داده در API.

16. **آیا در این درس درخواستی ارسال شده است؟** خیر.

## واژه‌نامه و چک‌لیست

**Object**: شیء؛ **Array**: آرایه؛ **Key**: کلید؛ **Value**: مقدار؛ **JSON Path**: مسیر اشاره؛ **null**: مقدار JSON صریح با معنای وابسته به قرارداد؛ **Defensive Parsing**: بررسی ساختار قبل از استفاده؛ **Escape**: فرار دادن کاراکتر.

- [ ] شش نوع مقدار JSON را می‌شناسم.
- [ ] `null` را از `""`، `0` و `false` تفکیک می‌کنم.
- [ ] خطاهای رایج را بدون ابزار پیدا می‌کنم.
- [ ] با JSON Path به مقدار تودرتو می‌رسم.
- [ ] قبل از حرکت روی Array، `null` را بررسی می‌کنم.
- [ ] هیچ نمونهٔ طراحی‌شده را دادهٔ واقعی نمی‌نامم.
