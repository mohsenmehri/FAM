بستهٔ اصلاح رفع خطای Port Security در FAM
==========================================

این بسته فقط فایل‌های برنامه را جایگزین می‌کند؛ پایگاه داده، تنظیمات شبکه، گواهی TLS، فایل .env و اطلاعات ورود سوئیچ داخل آن نیست.

محتوای بسته:
- server/equipment_mac_recovery.py (ماژول جدید بازیابی MAC sticky)
- server/equipment_ops.py (فعال‌سازی API اجرای بازیابی با تأیید)
- server/equipment_probe.py (گزارش امن خطاهای بازیابی)
- server/private_ui/FAM.html (نمایش MAC قدیمی/جدید و تأیید صریح کاربر)

روش نصب در VM فام:
1) بسته را به VM منتقل کن و در پوشهٔ پروژه‌ای قرار بده که docker-compose.yml داخل آن است.
2) از همان پوشه پشتیبان فایل‌های فعلی را بگیر:
   mkdir -p "$HOME/fam-before-mac-recovery"
   cp server/equipment_ops.py server/equipment_probe.py server/private_ui/FAM.html "$HOME/fam-before-mac-recovery/"
3) فایل ZIP را از همان پوشه استخراج و فایل‌ها را جایگزین کن. اگر ZIP در Downloads است:
   unzip -o "$HOME/Downloads/FAM-Linux-Lab-mac-recovery-update.zip"
4) سرویس برنامه را با سورس جدید بازسازی و اجرا کن:
   docker compose up -d --build app
5) گزارش راه‌اندازی را بررسی کن:
   docker compose logs --tail=80 app

اگر نام پوشهٔ پروژه یا محل ZIP متفاوت است، مسیرها را متناسب با سیستم خودت تغییر بده. استخراج باید از ریشهٔ پروژه انجام شود تا مسیرهای server/... درست جایگزین شوند.

رفتار بازنشانی sticky MAC:
- FAM فقط پورت‌های access فیزیکی VLAN 100 را می‌پذیرد که Err-disabled/disabled باشند، Port Security با maximum=1 و violation=shutdown داشته باشند و تخلف ثبت‌شده داشته باشند.
- در این روش هویت MAC بررسی یا تأیید نمی‌شود. FAM sticky MAC پورت انتخاب‌شده را پاک می‌کند، Port Security را فعال نگه می‌دارد، sticky learning را دوباره فعال می‌کند و پورت را shutdown/no shutdown می‌کند. دستگاهی که بعد از آن اولین فریم را بفرستد ممکن است به‌عنوان MAC sticky جدید یاد گرفته شود.
- پس از هر بار فعال‌سازی، FAM تا ۱۵ ثانیه تقریباً هر ثانیه وضعیت را می‌خواند؛ اگر زودتر دوباره Err-disabled شود، همان لحظه ادامه می‌دهد. اگر همان last-source MAC به‌صورت SecureSticky روی پورت access دیگری VLAN 100 همین سوئیچ ثبت باشد، فقط همان رکورد sticky را از پورت قبلی پاک می‌کند و بازنشانی پورت هدف را تکرار می‌کند؛ حداکثر دو بار تلاش مجدد.
- پس از هر توالی تنظیمات، FAM دستور write memory را اجرا می‌کند؛ تغییرات در startup-config ذخیره می‌شوند.
- این کار می‌تواند ارتباط پورت هدف و در صورت تعارض، پورت قبلی را قطع کند. فقط پورت‌های درست را انتخاب کنید؛ این روش برای تأیید هویت MAC نیست و علت‌های دیگر Err-disabled را خودکار رفع نمی‌کند.

این بسته به‌تنهایی روی VM نصب نشده است؛ پس از استخراج و بازسازی کانتینر، در FAM دوباره «بررسی تجهیزات» و «رفع خطا» را اجرا کن.
