# auto_10 — بازبینی و ادغام انتخابی توسط یکپارچه‌ساز

منبع `29b4468a0d8342b347583bbb80edf67251912cda`؛ ۱۴ بخش، واژه‌نامه، نمودار، مثال‌ها، تمرین، همه ۱۲ پرسش و گزینه‌ها و اسکریپت محلی بررسی شد. این بازبینی یکپارچه‌ساز است، نه بازبینی مستقل انسانی. پاسخ‌ها به‌ترتیب length، choice نمونه، تفکیک ابزارها، schema، key، ro، OpenConfig، leaf-list، grouping، augment، config false و مرز اجرا هستند.

در نسخه دریافتی IP نامعتبر با وجود سناریوی درس بررسی نمی‌شد، نام فیلد ناشناس پذیرفته می‌شد، پوشش Native «تقریباً ۱۰۰٪» و یکسان بودن نقش pyang و validator داده بیش‌ازحد کلی بود. مدل Python اکنون IPv4/prefix و کلیدهای ناشناخته قرارداد نمونه را بررسی می‌کند، ادعاهای متن اصلاح و choice بدون default case مشخص شد. `leafref` در واژه‌نامه با قید `require-instance` توضیح داده شد. محدودیت: Python regex مثال، پیاده‌سازی عمومی XSD regex نیست؛ مدل نمونه جامع YANG یا اعتبارسنج تولیدی نیست، ورود به تجهیزات یا آزمون pyang/libyang انجام نشده است. سناریوی دوم مرجع و بدون اجرای تجهیز است. نمونه‌های VLAN/choice، نوع بولی، فیلد ناشناخته، آدرس و یکتایی در `tests/test_auto_10_integration.py` آزموده شدند.

منابع [RFC 7950](https://www.rfc-editor.org/rfc/rfc7950)، [RFC 8340](https://www.rfc-editor.org/rfc/rfc8340) و [مستندات pyang](https://github.com/mbj4668/pyang)؛ پشتیبانی واقعی مدل، نسخه، قابلیت‌ها و روش اعتبارسنجی instance باید جداگانه روی تجهیزات/ابزار مقصد بررسی شود. کاتالوگ آنلاین و آفلاین شامل درس است؛ هیچ مهاجرت پیشرفتی ادعا نمی‌شود.
