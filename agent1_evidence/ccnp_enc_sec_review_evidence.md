## ۱. بررسی عمیق پاسخ‌های کوییز

### Q0: سیاست `CoPP` برای کنترل نرخ ترافیک خطاب به پردازندهٔ روتر در کدام بخش تنظیم می‌شود؟
- **پاسخ انتخاب [1]:** زیر بخش مجازی `control-plane` با `service-policy input` (و در پلتفرم‌ها/نسخه‌های پشتیبان، در صورت نیاز جهت `output`)
- **توضیح:** CoPP ساختار MQC را مستقیماً روی بخش `control-plane` اعمال می‌کند تا ترافیک ورودی به CPU (و در پلتفرم‌های پشتیبان ترافیک خروجی از آن) نرخ‌بندی شود.
- **وضعیت:** ✅ فنی صحیح

### Q1: خطرناک‌ترین اشتباه هنگام تست اولیهٔ `CoPP` روی یک روتر عملیاتی در شبکهٔ زنده چیست؟
- **پاسخ انتخاب [2]:** قرار دادن `exceed-action drop` با نرخ بسیار پایین روی `class-default` بدون استثنا کردن پروتکل‌های روتینگ و مدیریت
- **توضیح:** اگر بدون پوشش دادن OSPF/BGP/BFD/SSH نرخ سخت‌گیرانه یا Drop روی `class-default` بگذارید، تمام نشست‌های کنترلی روتر سقوط می‌کنند.
- **وضعیت:** ✅ فنی صحیح

### Q2: در امنیت رابط‌های **REST API** شبکه، بهترین روش برای ارسال اعتبارنامه (Credentials/Token) پس از ورود کدام است؟
- **پاسخ انتخاب [3]:** ارسال Token در هدر `Authorization` روی ارتباط رمزنگاری‌شدهٔ HTTPS/TLS
- **توضیح:** ارسال Bearer Token در هدر روی بستر HTTPS/TLS مانع افشای رمز در لاگ‌های URL و شنود در شبکه می‌شود.
- **وضعیت:** ✅ فنی صحیح

## ۲. بررسی عمیق راه‌حل تمرین‌ها

### Ex0 (ساده)
- **مهمته:** کدام دستور را باید در انتهای `access-class 25 in` روی `line vty 0 4` اضافه کنیم تا اتصال SSH از داخل VRF مدیریتی (`Mgmt-intf`) نیز اجازهٔ ورود پیدا کند؟
- **راه‌حل:** `access-class 25 in vrf-also`
- **وضعیت:** ✅ موجود و فنی صحیح

### Ex1 (متوسط)
- **مهمته:** یک توسعه‌دهنده برای دریافت اطلاعات وضعیت سوئیچ از کنترلر شبکه یک درخواست REST با آدرس `http://10.10.0.5/api/devices?api_key=Secret123` نوشته است. دقیقاً **سه آسیب‌پذیری امنیتی** در همین یک خط را فهرست و اصلاح امن آن را بیان کنید.
- **راه‌حل:** ۱) استفاده از **`http://` بدون رمزنگاری** -> باید `https://` با TLS 1.2/1.3 باشد.
۲) گذاشتن **`api_key` در Query Stringِ URL** (که در لاگ سرور، مرورگر و پروکسی ذخیره می‌شود) -> باید در هدر `Authorization: Bearer <token>` فرستاده شود.
۳) نبود چرخهٔ انقضا/توکن موقت و نیاز به تأیید گواهی سمت کلاینت (`verify=True`).
- **وضعیت:** ✅ موجود و فنی صحیح

### Ex2 (چالشی)
- **مهمته:** پیکربندی کامل سیاست **CoPP** خواسته‌شده در بخش `exercise` بالا (ACLها، Class-Mapها، Policy-Map و اعمال زیر `control-plane`) را روی Cisco IOS بنویسید.
- **راه‌حل:** `ip access-list extended ACL_CRITICAL`
` permit ospf any any`
` permit tcp any any eq bgp`
` permit tcp any eq bgp any`
`ip access-list extended ACL_ICMP`
` permit icmp any any`
`class-map match-all CM_ROUTING`
` match access-group name ACL_CRITICAL`
`class-map match-all CM_ICMP`
` match access-group name ACL_ICMP`
`policy-map COPP_POLICY`
` class CM_ROUTING`
`  police 512000 conform-action transmit exceed-action drop`
` class CM_ICMP`
`  police 64000 conform-action transmit exceed-action drop`
` class class-default`
`  police 2000000 conform-action transmit exceed-action transmit`
`control-plane`
` service-policy input COPP_POLICY`
- **وضعیت:** ✅ موجود و فنی صحیح

- **تحلیل:** در Cisco IOS دستور `access-class 50 in` به‌صورت پیش‌فرض تمام اتصالاتی را که از طریق VRFهای غیرجهانی (مثل `Mgmt-intf`) می‌آیند رد می‌کند، مگر اینکه کلمهٔ کلیدی `vrf-also` در پایان دستور آمده باشد....
- **اصلاح:** تغییر خط VTY از طریق کنسول به **`access-class 50 in vrf-also`** تا ACL روی اتصالات ورودی از داخل VRF مدیریتی نیز ارزیابی و مجاز شود....

## ۵. اشتباهات متداول

### myth 0: چون روی پورت ورودی WAN یک ACL نوشته‌ام که SSH را بسته، دیگر هیچ ترافیکی به CPU روتر نمی‌رسد و نیازی به CoPP نیست....
- **واقعیت:** روترها برای پروتکل‌های مسیریابی، ARP، ICMP، NTP و پاسخ‌های مدیریتیِ خودِ سیستم هم باید در پورت‌های داخلی و بیرونی بسته بگیرند؛ علاوه بر این، بسته‌های جعلی از سمت شبکهٔ داخلی یا ترافیکِ مجازِ بیش‌ازحد ...
- **تشخیص:** تفاوت `show processes cpu` هنگام طوفان بسته‌های خطاب به IP روتر در برابر ترافیک عبوری عادی از پورت‌ها....

### myth 1: در فراخوانی REST API اگر از `Basic Auth` (نام کاربری و رمز Base64) روی HTTP ساده استفاده کنیم امن است چون رمز تبدیل به رشتهٔ کدشده شده است!...
- **واقعیت:** **Base64 رمزنگاری نیست** و یک کدگذاری کاملاً برگشت‌پذیر و خوانا در چند میلی‌ثانیه است؛ بدون **TLS (HTTPS)** کل نام کاربری و رمز در سیم لو می‌رود....
- **تشخیص:** هرگز آدرس API نباید با `http://` شروع شود؛ همیشه `https://` با تأیید گواهی و توکن هدر لازم است....
