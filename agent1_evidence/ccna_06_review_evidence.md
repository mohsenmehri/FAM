### Q0: در معماری کنترلرهای SDN مانند Cisco Catalyst Center، رابط میان اسکریپت‌های کاربر/برنامه‌ها و کنترلر چه نام دارد و معمولاً از چه نوع API استفاده می‌کند؟
- **پاسخ انتخاب [2]:** Northbound API — معمولاً REST API روی HTTPS با فرمت JSON
- **توضیح:** سمت بالای کنترلر (به سمت برنامه‌ها و مهندسان) Northbound API است و عمدتاً از REST API با JSON استفاده می‌کند؛ سمت پایین (به تجهیزات) Southbound است.
- **وضعیت:** ✅ فنی صحیح

### Q1: کدام متد HTTP در REST API برای *ساختن یک منبع جدید* (Create) استفاده می‌شود و کد پاسخ موفق استاندارد آن معمولاً چیست؟
- **پاسخ انتخاب [1]:** POST — کد 201 (یا 200/202)
- **توضیح:** `POST` برای ایجاد منبع جدید (`Create`) به کار می‌رود و معمولاً کد `201 Created` (یا `200`/`202` در عملیات ناهمگام) برمی‌گرداند؛ `GET` برای خواندن و `DELETE` برای حذف است.
- **وضعیت:** ✅ فنی صحیح

### Q2: چرا Ansible در مقایسه با ابزارهایی مثل Puppet یا Chef برای شروع اتوماسیون تجهیزات شبکه سیسکو رایج‌تر است؟
- **پاسخ انتخاب [0]:** چون Ansible بدون نیاز به نصب نرم‌افزار Agent روی روتر و سوئیچ (Agentless، از طریق SSH/API) و با فایل‌های YAML کار می‌کند
- **توضیح:** تجهیزات شبکه (مانند روتر و سوئیچ IOS) معمولاً محیط بسته دارند و نصب Agent رویشان ممکن یا ساده نیست؛ Ansible به شکل Agentless و Push از طریق SSH و API متصل می‌شود.
- **وضعیت:** ✅ فنی صحیح

## ۲. بررسی عمیق راه‌حل تمرین‌ها

### Ex0 (ساده)
- **مهمته:** فایل JSON خراب زیر ۳ خطای نحوی دارد؛ آن‌ها را پیدا و نسخهٔ کاملاً معتبر JSON را بنویسید:
`{
  'device': "R1",
  "uptime": 420,
  "ports": ["Gi0/0", "Gi0/1",],
}`
- **راه‌حل:** خطاها: ۱) `'device'` باید `"device"` باشد؛ ۲) کامای اضافه بعد از `"Gi0/1"` در آرایه؛ ۳) کامای اضافه بعد از آرایه پیش از `}` پایانی.
نسخهٔ صحیح:
`{
  "device": "R1",
  "uptime": 420,
  "ports": ["Gi0/0", "Gi0/1"]
}`
- **وضعیت:** ✅ موجود و فنی صحیح

### Ex1 (متوسط)
- **مهمته:** در یک پلتفرم Intent-Based Networking مثل Catalyst Center، عملیات زیر هر کدام به کدام یک از این بخش‌ها مربوط می‌شوند: `Data Plane`، `Control Plane`، `Northbound API`، `Southbound API`، `Underlay` یا `Overlay`؟
۱) ارسال فریم‌های کپسوله‌شدهٔ VXLAN بین دو سوئیچ، ۲) درخواست JSON با متد GET از اسکریپت پایتون به کنترلر، ۳) مسیریابی IS-IS بین سوئیچ‌های فیزیکی زیرساخت، ۴) ارسال تنظیمات از کنترلر به سوئیچ با NETCONF.
- **راه‌حل:** ۱) `Overlay` (و در لایهٔ ارسال سخت‌افزاری داخل `Data Plane`)؛ ۲) `Northbound API`؛ ۳) `Underlay` (و در نقش تبادل مسیر `Control Plane` زیرساخت)؛ ۴) `Southbound API`.
- **وضعیت:** ✅ موجود و فنی صحیح

### Ex2 (چالشی)
- **مهمته:** شما یک اسکریپت Ansible Playbook برای افزودن `vlan 60` به ۳۰۰ سوئیچ نوشته‌اید و یک بار اجرا شده و روی همهٔ سوئیچ‌ها تنظیم شده است. همکارتان همان Playbook را برای بار دوم بدون هیچ تغییری روی همان ۳۰۰ سوئیچ اجرا می‌کند! در حالت ایده‌آلِ مفهوم **Idempotency** چه اتفاقی باید بیفتد و چرا این ویژگی در اتوماسیون شبکه حیاتی است؟
- **راه‌حل:** مفهوم **Idempotency** یعنی اجرای دوبارهٔ همان Playbook وقتی شبکه از قبل در وضعیت مطلوب قرار دارد، **هیچ تغییر اضافی روی تجهیزات ایجاد نکند** (`changed=0`، همه `ok`) و ترافیک یا جدول‌ها را تکان ندهد. این ویژگی حیاتی است زیرا اگر نصف اجرا روی سوئیچ ۱۵۰ قطع شد، مهندس می‌تواند با خیال راحت پس از رفع مشکل دوباره Playbook را بزند بدون اینکه روی ۱۵۰ سوئیچ اول تنظیمات تکراری یا اختلال بسازد.
- **وضعیت:** ✅ موجود و فنی صحیح

- **خطا:** اسکریپت پایتون پس از احراز هویت موفق به REST API کنترلر Catalyst Center، برای افزودن یک سایت جدید درخواست `POST` می‌فرستد اما با کد خطای `400 Bad Request` یا `415 Unsupported Media Type` رد می‌شود....

## ۵. اشتباهات متداول

### myth 0: در فایل JSON هم می‌توان مثل پایتون از نقل‌قول تکی `'key'` یا کامنت `//` و کامای آخر لیست استفاده کرد....
- **واقعیت:** استاندارد JSON بسیار سخت‌گیر است: تمام کلیدها و رشته‌ها حتماً باید با نقل‌قول دوتایی `"..."` نوشته شوند، هیچ کامنتی مجاز نیست و کامای اضافه (Trailing Comma) بعد از آخرین عنصر خطای Syntax می‌دهد....
- **تشخیص:** با اجرای `python3 -m json.tool file.json` یا `jq` بلافاصله اعتبار نحوی JSON را بررسی کنید....

### myth 1: برای اجرای Ansible روی سوئیچ‌های Catalyst باید حتماً روی خود IOS یک برنامهٔ Agent نصب کنیم....
- **واقعیت:** برتری کلیدی Ansible در شبکه همین **Agentless** بودن آن است؛ Control Node با SSH یا NETCONF/RESTCONF مستقیم به تجهیزات وصل می‌شود و نیازی به نصب نرم‌افزار روی روتر و سوئیچ ندارد....
- **تشخیص:** در Playbookهای شبکه خط `connection: ansible.netcommon.network_cli` (یا `httpapi`) را می‌بینید نه نصب بسته روی سوئیچ....
